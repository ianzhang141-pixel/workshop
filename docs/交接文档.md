# 日常工作台 · 交接文档

面向接手维护的人或 AI 助手（GPT 等）。读完这一份应该能独立改动并交付。

---

## 1. 这是什么

一个多用户的每日 / 每周 / 每月待办工作台。两层分类：**用户 → 板块**，每个用户有一个自动汇总的「综合总览」加任意多个细分板块。事项可以是简单打勾，也可以带一条多阶段流程（如稿件的 大纲 → 初稿 → 作图 → 审核 → 发布）。

- 线上地址：<https://claude.ai/artifact/LkGMtTRqeuUBxwcNBmMPM7>
- 代码：本仓库 `index.html`（**单文件**，HTML + CSS + JS 全在里面，无构建步骤、无依赖包）
- 分支：`claude/loving-rubin-iti5x2`

## 2. 怎么跑起来

| 场景 | 做法 | 数据存哪 |
|---|---|---|
| 本地看效果 | 浏览器直接打开 `index.html` | 浏览器 localStorage（离线模式），首次打开自动灌入示例数据 |
| 线上正式用 | 打开上面的 artifact 链接 | 该 artifact 的共享数据库，多设备 / 多人实时同步 |

页面用 `await window.claude.use("db")` 探测运行环境：拿得到就走共享数据库，拿不到（比如直接开本地文件）就自动退回 localStorage。**两条路径都要能跑**，改代码时别把离线分支写死。

## 3. 文件结构

```
index.html          全部代码（≈1430 行）
README.md           功能说明
docs/交接文档.md    本文件
docs/工作日志.md    变更记录
package/            可复制的完整打包：应用 + 数据快照 + 复制说明
```

`index.html` 内部顺序：

```
<meta> / <title> / Google Fonts <link>
<style>      设计令牌（:root 三套主题）→ 布局 → 组件 → 窄屏适配
<div class="app">  左侧导轨 .rail + 右侧 .stage（.topbar + #content）
<dialog id="dlg">  所有弹窗复用这一个元素
<script>     一个 IIFE，"use strict"，分区注释见下
```

`<script>` 内的分区（按注释找）：`基础工具` → `初始示例` → `状态` → `本地缓存` → `任务周期逻辑` → `选择与筛选` → `写入` → `渲染：左侧导轨 / 顶栏 / 任务卡片 / 正文` → `对话框` → `交互` → `导出备份` → `数据连接`。

**正文布局**：`renderContent()` 在总览下先渲染「所有事项」区（`allItemsFor()` 把三组摊平成一条清单），再按板块渲染成多列（`.columns` 网格 + 每列一个 `.col`）；单个板块时铺成卡片格（`.cards.grid`）。每列的内容由 `bucketsFor(tasks, key)` 算出三组——`day`（当天）/ `week`（本周内）/ `month`（本月截止）——再交给 `bucketCards()` 拼成小方格，单张卡片由 `taskCard()` 渲染。顶部那条 `.strip` 把本周七天、提醒、本周进度压在一行里。

「所有事项」用 `taskRow()` 渲染成表格行（`.rows` / `.rowhead` / `.row`），板块列仍用 `taskCard()` 渲染方格。`bucketsFor()` 返回四组：`day` / `week` / `month` / `overdue`，**待补只在看「今天」时才有值**（它是相对今天算的，翻到过去的日子再显示会很怪）。待补不再单独成块，而是并进表格（带 `.rowsep` 分隔）和各板块列（`待补` 小标签，每列最多 5 条）。

**同一事项会出现在多个区域**（所有事项 / 板块列 / 待补），所以 `taskCard()` 的 `opts.ns` 给 DOM id 加前缀防止撞车；`state.openNotes` 的键**不带**前缀，这样在哪个区域展开备注都一致。表格行的展开状态另存在 `state.openRows`，整块缩起状态是 `state.foldAll`（存 localStorage 的 pref）。`opts.compact` 用于待补方格，省掉说明和备注框让高度等齐。

## 4. 数据模型

四个文档。`config/*` 三个存结构，打卡记录按「用户 + 月份」聚合。

```jsonc
// config/users
{ "list": [ { "id":"u_shuaige", "name":"帅哥", "emoji":"🕶", "color":"#8593A8", "order":0 } ] }

// config/boards
{ "list": [ { "id":"b_jiaoyi", "userId":"u_shuaige", "name":"交易", "icon":"📈", "order":1 } ] }

// config/tasks
{ "list": [ {
    "id":"t_mm1", "userId":"u_xiaozhu", "boardId":"b_meimei",
    "title":"今日稿件",
    "repeat": { "kind":"daily" },          // 见下表
    "stages": ["大纲","初稿","作图","审核","发布"],  // 空数组 = 简单打勾
    "note":"固定说明",
    "order":0,
    "start":"2026-09-16"                    // 创建日期，早于它的周期不算逾期
} ] }

// logs/<userId>_<YYYY-MM>
{ "userId":"u_shuaige", "month":"2026-09",
  "entries": {
    "t_zm1__2026-09-16": { "d":true, "s":-1, "n":"备注", "t":1789... }
    //  ↑ taskId__周期键        完成   阶段序号  当期备注  时间戳
  } }
```

### repeat 的六种形态

| kind | 额外字段 | 周期键 | 出现在 |
|---|---|---|---|
| `daily` | — | `YYYY-MM-DD` | 当日事项 |
| `weekly` | `days:[0-6]`（0=周日） | `YYYY-MM-DD` | 当日事项（仅选中的星期） |
| `weekany` | — | 该周**周一**的日期 | 「本周内完成」区 |
| `monthly` | `day: 1..28 \| "end"` | `YYYY-MM` | 「月度截止事项」区，带倒计时 |
| `once` | `date:"YYYY-MM-DD"` | `YYYY-MM-DD` | 当日事项（快捷添加框用这个） |
| `dates` | `list:["YYYY-MM-DD", ...]` | `YYYY-MM-DD` | 当日事项（命中列表的那几天） |

前四种还可带生效区间：`from` / `to`（起止日期），或 `times`（重复 N 次）。**`times` 在保存时就换算成 `to`**（`nthOccurrence()`），渲染时只看 `from`/`to`，不必逐日数——改这块时保持这个约定，否则每次渲染都要跑循环。

## 5. 必须知道的五个坑

1. **数据库快照是冻结对象。** `snap.data()` 返回的东西被 `Object.freeze` 过，严格模式下往上写会抛 `TypeError`，界面就"点了没反应"。凡是存进 `state` 的快照数据一律先 `clone()`（见 `attachConfig` / `syncLogSubs`）。v1 的打勾失效就是这个原因。
2. **文档总数上限 5000。** 所以打卡记录按月聚合成一个文档，**不要**改成一条记录一个文档——两个用户每天几条，一年就撑爆了。
3. **页面没有 `<html>` / `<head>` / `<body>` 外壳**，发布时由平台注入。别自己加。
4. **外部资源受 CSP 限制**：脚本只能来自 cdnjs 或 jsdelivr，样式表只能来自 Google Fonts，其它一律被拦截且没有报错。目前项目零外部脚本，尽量维持。
5. **写入要串行**：同一个文档不要并发写。`saveEntry()` 先改本地并重渲染（乐观更新），再写库；`update()` 失败（文档还不存在）会退回 `set()`。

## 6. 常见改动配方

**换配色** → 只改 `<style>` 顶部的 `:root` 令牌。三处必须同步改：`:root`（浅色）、`@media (prefers-color-scheme: dark)` 里的 `:root:not([data-theme="light"])`、以及 `:root[data-theme="dark"]`。组件样式一律引用令牌，**不要**把颜色字面量写进组件规则，否则会出现"深色主题里浅色文字配浅色底"。

**加一种重复方式** → 依次改：`occursOn()`（判断某天是否出现）、`periodOf()`（周期键）、`repeatLabel()`（列表上的小标签）、`openTaskDialog()` 的 `kinds` 数组 + `sync()` 显隐 + `onSubmit()` 组装。若是「一期跨多天」的类型，还要在 `renderContent()` 里给它单开一个区。

**加一个状态预设** → `STAGE_PRESETS` 加一项，再在 `openTaskDialog()` 的 `#f-stagequick` 里加一个 `data-fill="<key>"` 的按钮。状态列表本身由对话框内的 `stageList` 数组 + `drawStages()` / `readStages()` 维护，增删改名调序都在那儿。注意 `readStages()` 要在每次改动数组前先调用一次，否则用户正在输入的名字会丢。

**改列宽 / 每行列数** → `.columns` 的 `minmax(256px,1fr)`，以及 `.content` 的 `max-width`。

**改统计口径** → `dayStats()` / `streakOf()` / `overdueList()` 三个函数，都在「选择与筛选」区。顶栏大数字、侧栏「总览」、「所有事项」区三处口径必须一致，都走 `allItemsFor()` + `doneCount()`——之前顶栏只算当日、所有事项还算月度，两边对不上。

**调整排序** → `sinkDone()` 负责把已完成的沉到列尾，在 `bucketsFor()` 里对三组分别调用。`Array.sort` 是稳定的，靠这个保持原有顺序。

## 7. 发布

线上页面托管在 Claude 的 Artifact 平台上，**只有 Claude 能把新版本发布到同一个 URL**（工具调用 `Artifact`，传 `url` 指向上面那个地址）。其它助手（GPT 等）可以照常修改 `index.html` 并提交到仓库，但要让线上生效，需要：

- 让 Claude 重新发布同一文件；或
- 把 `index.html` 自行托管到别处（静态托管即可）。自行托管时 `window.claude` 不存在，页面会走 localStorage 离线模式——数据不再跨设备同步，需要另接后端。

改完请务必：本地打开跑一遍（打勾、加事项、切用户、切日期），再提交。

## 8. 已知限制

- **提醒只在页面内**：顶部提醒条 + 倒计时。artifact 运行在沙箱里，发不出系统通知 / 推送，必须打开页面才看得到。
- **连续全勤最多回溯 60 天**，且只订阅当前月前后各一个月的打卡文档，更早的历史不参与统计。
- **待补事项只看最近 14 天**。
- **没有导入功能**，只有导出 JSON 备份（依赖 `downloads` 能力，拿不到时按钮自动隐藏）。
- **深浅色跟的是宿主应用的主题**，不是操作系统。页面嵌在 claude.ai 的 iframe 里，`prefers-color-scheme` 取的是宿主的已用配色，所以只有当 Claude 应用主题设为「跟随系统」时才会跟着电脑走。页面因此自带一个开关：写 `data-ui-theme` 到根元素，对应的 CSS 块放在宿主的 `[data-theme]` 规则**之后**，靠后来居上压过去。
- **状态被删减后**，历史打卡里存的阶段序号可能越界；`taskCard()` 用 `Math.min(st, stages.length-1)` 夹住，读起来是「停在最后一段」。
- **并发写是"最后写入者获胜"**，没有事务。两人同时改同一条结构配置有可能互相覆盖；打卡记录按条 `update` 合并，实际冲突概率很低。
