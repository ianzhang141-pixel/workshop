## v6 — 2026-09-16

### 修复：事项删除点了没反应

**根因**：`window.confirm()` 在沙箱 iframe 里被浏览器直接忽略并返回 `false`。页面跑在带 `sandbox` 但没有 `allow-modals` 的 iframe 中，控制台只留一句
`Ignored call to 'confirm()'. The document is sandboxed, and the 'allow-modals' keyword is not set.`
删除代码写的是 `if(!confirm(...)) return;`，于是永远在这一行返回——四条删除路径（卡片/表格行上的删除按钮、事项弹窗里的删除、板块删除、用户删除）全部失效。

**为什么之前没测出来**：我一直把 `index.html` 当顶层页面打开来测，Playwright 会自动接管并接受原生弹窗，删除看上去是好的。真实环境是 iframe 且不带 `allow-modals`，两者行为完全相反。

**修法**：新增第二个 `<dialog id="confirmDlg">` 和 `askConfirm()`，四处 `confirm()` 全部替换。`<dialog>.showModal()` 是 DOM API，不受 `allow-modals` 限制，在沙箱里正常工作。顺便把确认文案写得具体了些——删用户会显示"其 3 个板块、4 条事项将一并删除"。

**验证**：搭了个宿主页把 `index.html` 嵌进 `sandbox="allow-scripts allow-same-origin allow-forms"` 的 iframe 里测。先确认该环境下 `confirm()` 确实返回 `false`，再逐条走：表格行删除（取消→条数不变；确定→6 条变 5 条）、事项弹窗内删除（编辑弹窗同时关闭）、板块删除（列数 4→3）、用户删除文案。全程没有任何原生弹窗事件触发，零报错。

**教训已写进交接文档第 5 节**，作为第 6 个坑：涉及浏览器原生能力的代码，必须在沙箱 iframe 里验证，不能只在顶层页面测。

## v5 — 2026-09-16

### 「所有事项」改成表格
从方格改成一行一条的表格：事项 / 板块 / 周期 / 状态 / 操作五列，窄屏自动折成两行。新增 `taskRow()`；板块列仍然是方格（`taskCard()`），两种形态各司其职——上面用来通览，下面用来分门别类。

保留了两层「缩略」：整块可一键缩起（只留一行完成数统计，状态存 localStorage），单行可展开看状态条和当期备注。

### 待补事项并入当日
不再单独占一块。`bucketsFor()` 多返回一组 `overdue`，并进两处：表格里跟在当日事项后面，用一条 `.rowsep` 分隔、标题标红；各板块列里作为「待补」小标签下的几张方格（每列最多 5 条）。

`overdue` **只在看「今天」时才有值**——它是相对今天算的，翻到过去的日期还显示"待补"会很怪。

### 打包成可复制的工作台
新增 `package/`：单文件应用 + 现有全部内容的数据快照（2 个用户、8 个板块、11 条事项、2 份打卡记录）+ 一份「空白结构」（保留用户和板块、事项清空）+ 复制说明。同时打了 `工作台-完整打包.zip`。

数据是从线上库读出来的真实内容，原样打包不做任何改动——包括用户自己新建的「✅ 日常」板块、改名后的事项，以及两条重名的「递签」。

验证：解压后用浏览器直接打开，离线模式正常启动、四个板块列渲染正确、零报错；三个 config 文件条数与线上一致。

## v3 — 2026-09-16

### 主区改成「一个板块一列，事项向下排成小方格」
原来的布局是一条条通栏横排堆下来（提醒条、统计四宫格、本周节奏、今日事项面板…），竖着吃掉大量空间。改成：

- 顶部只剩**一条细条**：本周七天 + 提醒 chips + 本周进度 / 连续天数，挤在一行里。
- 主区综合总览按板块**横向分列**，每列内事项是紧凑的小方格卡片；「本周内」「本月截止」作为小标签并入各自板块那一列，不再单独占一整块。
- 单个板块视图铺成自适应卡片格。
- 内容区限宽从 1080px 放宽到 1680px，左栏 266→228px——原先四个板块只能排三列，第四列被挤到第二行留下大片空白。

### 事项的删除 / 重命名做成常驻可见
之前编辑入口是悬停才浮现的 `⋯`，手机上没有悬停，等于这功能不存在——用户反馈"没有删减和重命名功能"，其实是找不到。现在每张卡片常驻三个图标按钮（备注 / 编辑 / 删除），点标题也能直接进编辑；删除带二次确认。

### 状态（进度阶段）可增删改名调序
原来只能在下拉里选预设，或往一个文本框里填顿号分隔的字符串。改成真正的编辑器：每个状态一行，可改名、上移、下移、删除，底下「＋ 添加一个状态」；「稿件流程」「复盘流程」降级成一键填入的按钮。用户说得对——"初稿、大纲、作图、审核只是举例"。

状态被删减后历史记录里的序号可能越界，渲染时用 `Math.min(st, len-1)` 夹住。

### 不再预置常驻事项
删掉当初我自己编的七条示例（每日学习打卡、本周学习计划复盘、采购原料、早起、运动 30 分钟、大扫除、本周买菜囤货）。线上库里用户已经改过的（今日稿件 → 可丽金眼霜、今日甜点出品都改成了单次）和自己新建的（Olay修改）全部原样保留——写库前先读了一遍当前版本，按 id 精确剔除，并用 `if_version` 钉住版本号防止覆盖。

保留的是用户在第一条需求里明确点名的：交易复盘（每天）、检查数据更新 / 成交更新（每天）、个体户税务三条（每月）。

### 页面自带配色主题开关
用户反馈"配色不跟随电脑系统"。根因不是 CSS 写错：页面嵌在 claude.ai 的 iframe 里，`prefers-color-scheme` 取的是宿主的已用配色，所以跟的是 **Claude 应用的主题设置**而非操作系统，只有应用设为「跟随系统」时才会跟着电脑走。

与其受制于宿主，左下角加了 跟随 / 浅色 / 深色 三档开关：写 `data-ui-theme` 到根元素，对应 CSS 块放在宿主 `[data-theme]` 规则之后压过去，选择存 localStorage。

### 验证
模拟数据库（深度冻结快照）跑完整路径：4 列渲染正确；打勾、删除、列内临时事项回车添加均生效；状态编辑器做了"填入预设 → 改第 1 个名字 → 删第 4 个 → 第 1 个下移 → 新增第 5 个"，存库结果与界面一致；主题开关写入正确；浅色 / 深色 / 390px 窄屏三张截图均无报错。

### 修复：事项无法打勾
**根因**：数据库快照返回的对象是 `Object.freeze` 过的，而代码在严格模式下直接往上面写入，抛 `TypeError`，界面表现为"点了没反应"。同一个问题也会让新建 / 编辑事项失败。离线模式不受影响，所以第一版自测时没暴露。

**修法**：`attachConfig()` 和 `syncLogSubs()` 里存进 `state` 之前先 `clone()`。

**验证**：写了一个会返回深度冻结快照的模拟数据库（`playwright` + `addInitScript`）跑真实代码路径，连点三个勾 + 切一次阶段，`errors: []`，打卡文档正确写出。

### 已完成的沉到最下方
新增 `sinkDone()`，未完成在前、已完成在后；`groupByBoard()` 里整组做完的板块也整体下沉。`Array.sort` 稳定，组内原有顺序不变。已完成行加了 `opacity:.62`，悬停恢复。

### 顶栏「添加事项」按钮 + 更多重复方式
顶栏右侧加常驻按钮。事项对话框扩了两类能力：

- **持续时间**：长期有效 / 指定起止日期 / 重复 N 次后结束。N 次在保存时用 `nthOccurrence()` 换算成结束日期存进 `to`，渲染时不必逐日数。
- **自定义多个日期**（`kind:"dates"`）：挑几个不连续的日子，用日期胶囊增删。

**验证**：逐一切换六种重复方式 × 三种持续时间，检查八个字段块的显隐组合全部正确；实建一条「每周一、从 9/21 起、共 3 次」，得到 `to: 2026-10-05`（9/21、9/28、10/5）。

### 顺手修的
- 自带 `[hidden]{display:none!important}`，不再依赖宿主的重置样式——否则 `.field{display:flex}` 会盖掉 `hidden`，对话框里该藏的字段藏不住。

## v1 — 2026-09-16

初版。单文件 `index.html`，发布为 Artifact，用共享数据库持久化。

- 两层分类：用户 → 板块；每个用户一个综合总览 + 任意细分板块，均可增删改
- 五种重复方式：每天 / 每周指定星期 / 每周内完成 / 每月截止日（含月底）/ 指定日期
- 多阶段流程（稿件流程、复盘流程、自定义），点阶段标注状态，点当前阶段退回上一步
- 提醒条、本周节奏条、当日 / 本周进度、近 14 天待补、连续全勤
- 每期事项可写当期备注
- 导出 JSON 备份

按用户给的例子灌了初始数据：帅哥（学习 / 交易 / 自媒体 / 个体户税务）、小猪（美美 / 甜点 / 日常）。学习和甜点两个板块用户没给具体事项，放了占位示例。

**当时做的两个判断**（沿用至今）：

1. 打卡记录按「用户 + 月份」聚合成一个文档，而不是一条一个文档——数据库总量上限 5000 个文档，两个用户每天几条，一年就撑爆。
2. 事项带 `start` 字段记录创建日期。早于 `start` 的截止期不算逾期，而是顺延到下一期，避免新建的月度事项一上来就显示"已逾期"。

### 发布后发现的问题
打勾失效（见 v2）。教训：只在离线模式下自测不够，涉及数据库能力的代码要连数据库路径一起验证。
