# 复制一个新的工作台

这个文件夹是「工作台」的完整打包，拿着它就能再开一个一模一样的。

## 包里有什么

```
index.html              整个工作台，单文件，HTML + CSS + JS 全在里面
数据-当前内容/           现有工作台的全部内容（2 个用户、8 个板块、11 条事项、2 份打卡记录）
  config-users.json       用户
  config-boards.json      板块
  config-tasks.json       事项
  logs-<用户id>_<年-月>.json  打卡记录（哪天做了什么、做到哪个状态、当期备注）
数据-空白结构/           只保留用户和板块，事项清空、不带打卡记录
  config-users.json
  config-boards.json
  config-tasks.json
复制新工作台.md          本文件
```

**要连人带事整份复制**，用「数据-当前内容」。
**只想沿用同样的用户和板块、事项从零开始**，用「数据-空白结构」。
**完全从头开始**，三个 config 文件都不用导入，打开就是空的，自己建用户和板块。

---

## 方法一：再开一个联网版（推荐，多设备同步）

把这个文件夹发给 Claude，说：

> 帮我用这个文件夹里的 index.html 新建一个工作台 Artifact，
> capabilities 设成 `{"db": {}, "downloads": true}`，
> 发布后把「数据-当前内容」里的三个 config 文件写进它的数据库：
> config/users、config/boards、config/tasks，
> 文件内容就是文档正文。打卡记录也一并导入 logs 集合，文档 id 用文件名里 `logs-` 后面那一段。

要点（给接手的人或 AI 看）：

- 发布时 **必须** 声明 `capabilities: {"db": {}, "downloads": true}`，否则数据存不住、也没有导出按钮。
- 数据库文档路径是固定的：`config/users`、`config/boards`、`config/tasks`，打卡记录是 `logs/<用户id>_<年-月>`（例如 `logs/u_shuaige_2026-09`）。
- 每个 config 文档的正文就是 `{"list": [...], "updatedAt": 0}`，直接把文件内容整个写进去。
- 新工作台是**独立**的：和原来那个不共享数据，各改各的。

## 方法二：本地单机用

直接用浏览器打开 `index.html` 就能用，数据存在这台电脑的浏览器里。

- 不需要联网，也不需要任何服务器。
- 但**不跨设备、不跨浏览器**，换台电脑就是空的；清浏览器数据会丢。
- 首次打开会自动放几条示例事项（就是你第一次提的那些），删掉即可。

想把现有内容导进本地版：打开页面按 F12 → Console，粘贴执行

```js
localStorage.setItem('workbench.data.v1', JSON.stringify({
  users:  /* config-users.json 里的 list 数组 */ [],
  boards: /* config-boards.json 里的 list 数组 */ [],
  tasks:  /* config-tasks.json 里的 list 数组 */ [],
  logs:   { "u_shuaige_2026-09": { /* logs-... 文件里的 entries 对象 */ } }
}));
location.reload();
```

## 方法三：放到自己的服务器

`index.html` 是纯静态文件，扔到任何静态托管上都能开。此时页面检测不到 Claude 的数据库能力，会自动退回本地存储模式（同方法二的限制）。要真正的多人多设备同步，得自己接一个后端。

## 数据长什么样

```jsonc
// 用户
{ "id":"u_shuaige", "name":"帅哥", "emoji":"🕶", "color":"#8593A8", "order":0 }

// 板块（归属某个用户）
{ "id":"b_jiaoyi", "userId":"u_shuaige", "name":"交易", "icon":"📈", "order":1 }

// 事项
{ "id":"t_jy1", "userId":"u_shuaige", "boardId":"b_jiaoyi",
  "title":"交易复盘",
  "repeat":{ "kind":"daily" },        // 见下表
  "stages":["记录","分析","结论"],     // 空数组 = 打勾即完成
  "note":"固定说明", "order":0,
  "start":"2026-09-16" }              // 创建日期，早于它的周期不算逾期

// 打卡记录：按「用户 + 月份」聚合成一个文档
{ "userId":"u_shuaige", "month":"2026-09",
  "entries": { "t_jy1__2026-09-16": { "d":true, "s":2, "n":"备注", "t":1789... } } }
//             事项id__周期键            完成  当前状态序号  当期备注  时间戳
```

`repeat.kind` 的六种：

| kind | 额外字段 | 含义 |
|---|---|---|
| `daily` | — | 每天 |
| `weekly` | `days:[0-6]`，0=周日 | 每周指定星期 |
| `weekany` | — | 每周内完成即可 |
| `monthly` | `day: 1..28` 或 `"end"` | 每月某日前 / 月底前 |
| `once` | `date:"YYYY-MM-DD"` | 只在这一天（新建时的默认） |
| `dates` | `list:["YYYY-MM-DD",...]` | 自定义的若干天 |

前四种还可加 `from` / `to`（起止日期）或 `times`（重复 N 次，保存时换算成 `to`）。

改代码之前请先读仓库里的 `docs/交接文档.md`，尤其是「必须知道的五个坑」——数据库快照是冻结对象、文档总数上限 5000 之类，踩过一次。
